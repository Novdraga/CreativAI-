## 1. Content Philosophy

Stackwise content exists to **support creator decisions**, not to generate pageviews. Every piece of content must move a user closer to a confident tool or workflow decision.

### Content Principles

| # | Principle | Implication |
|---|-----------|-------------|
| 1 | **Decision-first** | Every page answers a specific decision question |
| 2 | **Evidence-backed** | Claims cite sources; scores cite methodology |
| 3 | **Creator-contextualized** | Written for creators, not tech audiences |
| 4 | **Honest** | Report limitations and negatives, not just positives |
| 5 | **Current** | Data is verified regularly; stale content is flagged |
| 6 | **Depth over breadth** | 20 deeply evaluated tools > 200 shallow listings |

## 3. Content Types — Priority Ordered

### Priority 1: Alternatives

**Why first:** "X alternatives" queries have high search volume and strong decision intent. Users actively looking to switch represent high-value traffic.

**Structure per page:**
- Why users look for alternatives (common reasons)
- Categorized alternatives: cheaper, better quality, easier, free
- P.A.C.E. scores for each alternative
- Key differentiator for each
- Migration considerations (where applicable)
- Verdict: best overall alternative

### Priority 2: Comparisons

**Why second:** "X vs Y" queries are the strongest purchase-intent signal. Two-tool comparisons are the atomic unit of decision support.

**Structure per page:**
- Quick verdict (above the fold)
- Side-by-side P.A.C.E. comparison
- Feature comparison table
- Pricing comparison
- "Best for [use case]" verdicts
- Detailed analysis per dimension
- Methodology note

### Priority 3: Creator Stacks

**Why third:** Stack guides deliver Stackwise's unique value proposition — workflow-level recommendations that no competitor offers.

**Structure per page:**
- Use case overview and target persona
- Complete stack with tool selections
- Cost breakdown
- Reasoning per tool selection
- Alternative tools per position
- Getting started guide
- Budget variations (free tier, mid-range, premium)

### Priority 4: Best-For Pages

**Why fourth:** High-volume category queries. These pages serve as entry points for users who haven't narrowed their search yet.

**Structure per page:**
- Clear top recommendation with reasoning
- Ranked list with P.A.C.E. scores
- Constraint-based recommendations (best free, best for beginners, best quality)
- Key differentiators between options
- Pricing summary

### Priority 5: Tool Pages

**Why fifth:** Individual tool pages are essential infrastructure. They support all other content types.

**Structure per page:**
- Tool overview and positioning
- P.A.C.E. scores with evidence summary
- Pricing breakdown
- Key features
- Limitations
- Commercial rights
- Related comparisons and alternatives
- Affiliate CTA with disclosure

### Priority 6: Educational Content (Post-MVP)

**Why later:** Educational content builds authority but doesn't directly support tool decisions. Defer until core decision content is solid.

**Potential topics:**
- "How to build a faceless YouTube workflow"
- "Understanding AI voice commercial rights"
- "AI tool budgeting for solo creators"

## 4. Editorial Standards

### Writing Quality

| Standard | Requirement |
|----------|------------|
| **Voice** | Informative, direct, helpful. Not salesy, not academic. |
| **Perspective** | Second person ("you") when addressing the reader. First person plural ("we") when describing Stackwise methodology. |
| **Jargon** | Avoid technical jargon. Define terms on first use. |
| **Length** | As long as needed, no longer. Minimum 500 words for decision content. |
| **Formatting** | Use headers, lists, tables, and visual breaks. Walls of text are unacceptable. |
| **Specificity** | Concrete numbers and examples, not vague claims. "Costs $10/month" not "affordable." |

### Content Quality Checklist

Before any content is published:

- [ ] Answers a specific decision question
- [ ] All facts verified against primary sources (with dates)
- [ ] P.A.C.E. scores backed by evaluation data
- [ ] Pricing is current and verified
- [ ] Limitations are included, not just positives
- [ ] Affiliate relationships disclosed
- [ ] Last-verified date included
- [ ] Reviewed by at least one other agent or human
- [ ] Title and meta description are unique and accurate
- [ ] Internal links to related content included

## 5. AI-Assisted Content Policy

### Permitted AI Use

| Use Case | Permitted | Condition |
|----------|-----------|-----------|
| First draft generation | ✓ | Must be reviewed and edited by human/senior agent |
| Data formatting | ✓ | Data must be verified independently |
| Content structure | ✓ | Structure must follow content type template |
| Proofreading | ✓ | — |
| Research synthesis | ✓ | Sources must be independently verified |

### Prohibited AI Use

| Use Case | Prohibited | Reason |
|----------|-----------|--------|
| Unsupervised publication | ✗ | All content requires editorial review |
| Fabricating evaluation data | ✗ | Data integrity is non-negotiable |
| Generating opinions as facts | ✗ | Violates information classification |
| Copying competitor content | ✗ | Legal and ethical issues |
| Generating fake user testimonials | ✗ | Trust violation |

### AI Disclosure

Stackwise does not need to disclose AI assistance on every page (this is common industry practice), but:
- The About page should acknowledge that AI tools assist with content production
- The methodology page should be clear about human oversight in evaluations
- If a specific piece of content is entirely AI-generated, it must be disclosed

|-------------|-------------|-------------------|

| Comparison pages | Every 90 days | Either tool updated |

### Reactive Updates

| Trigger | Response Time | Action |
|---------|--------------|--------|
| Tool pricing change | Within 3 days | Update pricing data |
| Tool shutdown | Within 1 day | Add notice, update alternatives/stacks |
| Major feature launch | Within 7 days | Update features, consider re-evaluation |

### Version History

- Major content updates should note "Updated [date]: [what changed]"
- Historical data is preserved, not silently overwritten
- The `lastUpdatedAt` date always reflects the most recent substantive change

## 7. Source Requirements

### Minimum Source Standards

| Claim Type | Minimum Source |
|-----------|---------------|
| Pricing | Official pricing page (URL + access date) |
| Features | Official documentation or verified hands-on testing |
| Performance | P.A.C.E. evaluation per protocol |
| Market claims ("most popular") | Third-party data citation required |
| Comparative claims ("faster than X") | Hands-on testing data required |

### Source Documentation

Every content page must maintain:
- A list of sources used (URLs + access dates)
- The date each data point was verified
- The evaluation version referenced (for P.A.C.E. data)

## 8. Fact Verification

### Verification Process

1. **Claim identification** — Identify all factual claims in content
2. **Source check** — Verify each claim against the source hierarchy
3. **Cross-reference** — For significant claims, verify against at least two sources
4. **Date stamp** — Record when verification occurred
5. **Confidence note** — Flag claims that could not be fully verified

### Common Verification Failures

| Failure | Response |
|---------|----------|
| Pricing page changed since verification | Re-verify and update |
| Feature claimed but not testable | Note as "listed but not tested" |
| Conflicting information from tool | Note conflict, use primary source |
| Tool website is down | Note as "temporarily unverifiable" |

## 9. Disclosure Policy

### Affiliate Disclosure

**Required on every page that contains affiliate links:**

> **Disclosure:** Stackwise may earn a commission when you sign up through links on this page. This does not affect our scores or recommendations. Our P.A.C.E. methodology is applied consistently regardless of affiliate relationships. [Learn about our methodology →]

### Placement

- **Visible before the first affiliate link** on the page
- Also included in the page footer
- The methodology page explains the separation between affiliate revenue and scoring in detail

### Sponsored Content

If sponsored content is ever introduced (Post-MVP):
- Must be clearly labeled as "Sponsored" or "Promoted"
- Must NOT appear in P.A.C.E. rankings or comparison verdicts
- Must be visually distinct from editorial content

## 10. Human Review Requirements

### What Requires Human Review

| Item | Review Required |
|------|----------------|
| New tool page publication | Yes |
| P.A.C.E. score changes ≥2 points | Yes |
| New stack recommendations | Yes |
| Comparison verdicts | Yes |
| Best-for page recommendations | Yes |
| Pricing updates (data only) | No (automated verification sufficient) |
| Metadata/SEO updates | No |

### Review Process

1. Content creator (agent or human) produces draft
2. Reviewer checks against editorial standards checklist
3. Reviewer verifies factual claims and sources
4. Reviewer approves or requests changes
5. Published content includes "reviewed" status
